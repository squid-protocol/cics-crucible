# hc-fetch-nosuspend: FETCH CHILD and FETCH ANY with NOSUSPEND, NOTFINISHED against NORMAL, NOTFND and INVREQ

## The trap

HCNS (HCNSPR) reads its mode from the terminal input (`HCNS C`, `A`, `N`). It logs one 24-byte record per FETCH to TS
queue HCNLOG, `R=rrr/sss C=c A=aaaa T=t`: RESP, RESP2, the COMPSTATUS (`N` NORMAL, `A` ABEND, `-` not read), the ABCODE
and whether the token FETCH ANY returned equals the one RUN returned (`Y`/`N`, `-` when not asked). FETCH is not a SPEC
event (only RUN is), so its outcome is observed through these records, as in `hc-fetch-child`. HCNC (HCNSCH) is the
child: `DELAY INTERVAL(5)`, `WRITEQ TS` `CHILD RAN` to HCNCLOG, RETURN.

* `C`: `RUN TRANSID('HCNC') CHILD`, `FETCH CHILD NOSUSPEND` at once, `DELAY INTERVAL(10)`, `FETCH CHILD NOSUSPEND` again.
* `A`: the same with `FETCH ANY NOSUSPEND`, and a third one after the child has been fetched.
* `N`: `FETCH ANY NOSUSPEND` by a task that has run no child.

The parent's 10 s wait is longer than the child's 5 s, so the second FETCH finds a completed child.

## Why a naive translation breaks

* A port that implements FETCH by always waiting for the child (the `hc-fetch-child` behaviour) ignores NOSUSPEND: the
  first FETCH of `C` and `A` would return NORMAL, not NOTFINISHED.
* A port that answers NOSUSPEND with NOTFND, or a not-yet-complete child with INVREQ, gets the RESP wrong: NOTFINISHED
  (RESP 113) with RESP2 52 is "the child is not yet complete"; NOTFND RESP2 1 is "no unfetched children".
* A port that reports NOTFINISHED for a FETCH ANY NOSUSPEND with no children at all gets `N` wrong: that is INVREQ with
  RESP2 52 ("the parent has no children").
* A port that does not write COMPSTATUS / ABCODE or the token on a NORMAL NOSUSPEND fetch, or writes them on
  NOTFINISHED, shows it in the `C=` / `A=` / `T=` fields.

## Expected behaviour

Model (SPEC sections 2 and 4, register X18): one region, terminal T001, clock 2026-03-02T10:00:00. Each scenario is one
operator step (`HCNS <mode>`) at time 0. The parent is task 1; a child is task 2, with trigger `{"kind": "run", "task":
1, "event": 1}`. A RUN child is dispatched at the parent's next wait and ends at that instant plus its own DELAY, so the
child is dispatched at the parent's `DELAY INTERVAL(10)` and completes 5 s later, 5 s before the parent resumes.

* **`child-nosuspend`** (`C`): the child has not even been dispatched when the first FETCH runs, so it is not complete:
  "NOTFINISHED ... NOSUSPEND was specified, but the child is not yet complete" [FETCH-CHILD], RESP2 52, and the parent
  is not suspended: `R=113/052 C=- A=     T=-` (COMPSTATUS, ABCODE untouched). After the 10 s wait the child has
  completed (`CHILD RAN`), and the FETCH is NORMAL with COMPSTATUS NORMAL and a blank ABCODE: `R=000/000 C=N A=     T=-`.
* **`any-nosuspend`** (`A`): "NOTFINISHED ... NOSUSPEND was specified, but there were no completed children to fetch"
  [FETCH-ANY]: `R=113/052 C=- A=     T=-`. After the wait the first FETCH ANY returns the one child, whose token is the
  CHILD token of the RUN [RUN-TRANSID]: `R=000/000 C=N A=     T=Y`. The third finds no unfetched child left: NOTFND with
  RESP2 1 [FETCH-ANY]: `R=013/001 C=- A=     T=-`.
* **`no-children`** (`N`): a task that never ran a child gets INVREQ with RESP2 52 [FETCH-ANY], not NOTFINISHED:
  `R=016/052 C=- A=     T=-`.

## What a correct port must do

* Honour NOSUSPEND: return NOTFINISHED / RESP2 52 at once when the child (or, for ANY, every child) has not completed,
  without suspending the parent, and leave COMPSTATUS, ABCODE and the token area as they were.
* Complete the same FETCH NORMALLY once the child has ended, writing COMPSTATUS, ABCODE and (ANY) the token.
* Tell NOTFINISHED (RESP2 52, child still running) from NOTFND (RESP2 1, none left) and INVREQ (RESP2 52, no children).
* Run the child as task 2 at the parent's wait, and let the parent's DELAY pass the child's DELAY.

## Avoided ambiguities

* SPEC section 3 keeps a child's order against its parent unobservable. The scenarios do not depend on it: the first
  FETCH is NOTFINISHED whether the child has not started or is mid-DELAY (it cannot have completed, its first command is
  a 5 s DELAY), and the second FETCH comes 10 s later, after the child's end.
* A tie (child completing at the very instant the parent resumes, register X18) is avoided: 5 s against 10 s.
* FETCH CHANNEL is not used: the name of the channel a child leaves current is generated by CICS and cannot be stated.
  TIMEOUT is not used: IBM's maximum differs between the FETCH ANY and FETCH CHILD pages, and NOTFINISHED RESP2 53 is a
  separate mechanism.
* COMPSTATUS is read only when RESP is NORMAL, ABCODE is pre-set to blanks, and COMPSTATUS is compared with the numeric
  CVDAs NORMAL 1016 and ABEND 900 (the CVDA list), because DFHVALUE is not expanded in an IF.
* The expected logs are derived from IBM's text and the programs only, not from any emulator or port.
